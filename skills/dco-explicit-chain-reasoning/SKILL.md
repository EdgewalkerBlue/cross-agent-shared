# 显式思维链与中继自检

## 触发条件

适用：多跳因果关系、跨文件或跨文档推理、长代码逻辑追踪、数学与算法推导、需要留下可审计决策链的场合。

不适用：单跳事实查询、闲聊、格式转换、简单检索。挂载后输出长度会显著增加，短任务请勿启用。

## 核心原则

商业接口无法修改隐藏层权重，所以把原本发生在隐藏层的中继过程搬到可见的 token 空间里完成。代价是输出变长，收益是链路可审计、断层可定位、结论可复现。

**第一轮禁止给结论。** 这条是本 Skill 生效与否的分水岭。

## 执行流程

### 第一阶段 · 强制解引用展开

1. 列出问题涉及的全部实体，为每个实体给唯一标识。
2. 把所有代词、省略、隐含指代绑定到具体实体；无法绑定的单列为歧义项。
3. 画出依赖图谱：前置条件 → 中间结论 → 最终目标，逐级摊开。
4. 明写从前置条件推导到每个中间结论的完整过程，不得跳步。

本阶段结束时，链路骨架应已覆盖全部前置条件与中间节点。此时仍不得给答案。

### 第二阶段 · 中继信号自检

逐跳扫描以下四类问题：

| 类型 | 表现 | 处理 |
| --- | --- | --- |
| 逻辑断层 | 从 A 直接跳到 C，缺 B | 补出 B，或标注该跳依赖未知信息 |
| 模糊代词 | 「它」「这个方案」「上述结论」指代不清 | 回填唯一实体名 |
| 偷懒缩写 | 「以此类推」「同理可得」「显然」 | 展开被略去的步骤 |
| 无依据假设 | 引入未在前提中出现的事实 | 标为假设并单列，或改为 MISSING |

发现链路不完整，必须在**中继层先补全**，不得带缺口进入第三阶段。

### 第三阶段 · 收敛与结论输出

只有当全部推导步骤自洽、且已推到最底层实体时才允许总结。输出时：

- 结论必须能仅凭链上前提复现，读者不需要回看原始直觉。
- 保留不确定性：把未能补全的跳数写成显式缺口，而不是用推测填平。
- 若中途更改过任何定义，必须显式声明变更点。

## 硬性约束

- 禁用省略号、占位符、TODO、「以此类推」代替推导步骤。
- 未完成自检不得输出最终结论；此前的产出只能标注为草稿。
- 缺口不可补全时标注 MISSING，禁止编造来源或数据。

## 自检清单

- [ ] 每个代词都已绑定到唯一实体
- [ ] 依赖图谱覆盖全部前置条件
- [ ] 每步都能指出依赖的上一节点
- [ ] 不存在未经说明的跳跃
- [ ] 结论与前缀链一致，无中途换定义
- [ ] 已知缺口已显式列出，未被推测覆盖

## 与其它 Skill 的关系

- 需要更强的服从性边界时，叠加 `dco-constraint-audit-protocol`。
- 断层来自多代理协作时，补全请求走 `dco-skill-blackboard-orchestration`。
- 提升来自权重侧而非协议侧时，见 `dco-skill-relay-injection`。
