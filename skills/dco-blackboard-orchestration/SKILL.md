# 黑板与中继代理编排

## 问题

子代理之间点对点全连接通信有两个结构性缺陷：

1. **通信复杂度 O(n²)**：n 个代理两两同步，状态传输次数随规模二次方增长，延迟与成本同时起飞。
2. **幻觉传染**：每个代理持有一份自己理解的「事实副本」，错误沿全连接扩散，且事后无法判断哪份副本才是权威版本。

## 角色

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 黑板 | 全局单一事实来源，只读 + 增量写，保留版本链 | 不主动发起任务 |
| 事件总线 | 传递标签事件与状态增量 | 不做业务判断 |
| 中继代理（DCO） | 跨模块路由、摘要、去重、超时裁决、补全调度 | 不亲自做领域推导 |
| 子代理 | 执行局部任务，只读黑板、只写增量 | 不与其他子代理直连 |

## 状态协议

一切跨模块状态用结构化协议传递，自然语言只留给人类可读摘要。

```json
{
  "task_id": "DCO-05",
  "fact_ref": "BB-0007",
  "tag": "RELAY.FACT.DELTA",
  "state_delta": { "结论字段": "新值" },
  "confidence": 0.82,
  "evidence": ["来源引用"]
}
```

约束：

- `state_delta` 只写变化字段，禁止整份覆盖。
- `confidence < 0.6` 必须触发补全请求而非继续推进。
- `evidence` 为空数组时，该事实标记为待验证，不得作为下游前提。

## 流程

1. **派活**：中继代理按依赖图谱把节点分派给子代理，附最小必要上下文。
2. **执行**：子代理只读黑板快照，不做跨节点自由探索。
3. **回执**：以事件标签写回增量，不广播过程叙述。
4. **归档**：黑板按 tag 合并增量；同一事实出现互斥版本时保留版本链并标记待裁决。
5. **补全**：检测到链路断层时，中继代理派补全请求，取回结果后重连链路。
6. **收敛**：全部回执就绪后由编排层统一裁决，冲突必须披露而非抹平。

## 收敛判据

- 依赖图谱无待解节点。
- 每个节点有唯一归属回执。
- 互斥结论、孤立证据、来源冲突均已处理或显式标注为未定。
- 结论可被第三方仅凭黑板复现。

## 反模式

- 子代理两两私聊共享状态。
- 用自然语言长文广播同步，导致冗余与版本歧义。
- 黑板允许多主写入且不留版本链，冲突无法裁决。
- 中继代理顺手做领域判断，形成新的单点偏差。
- 关键节点缺失时用多数投票掩盖分歧。

## 自检清单

- [ ] 子代理之间无直连通道
- [ ] 所有状态变更都经过黑板或事件总线
- [ ] 增量写入可回放，历史版本可恢复
- [ ] 冲突项已标记，未被静默覆盖
- [ ] 通信开销随代理数线性增长
