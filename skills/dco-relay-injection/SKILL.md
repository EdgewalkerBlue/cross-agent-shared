# 早期层中继注入

## 现象诊断

长链推导中模型提前收敛、给出一半就收尾，**不是算力不足**，而是深层传递过程中早期的语义信号衰减：注意力在多层传递后被稀释，模型误判「信息已足够」，触发停机。

区分方法：同一任务拆成若干 3 跳以内的小链，成功率正常；合并成长链后骤降。若短链也差，问题在数据或提示词，不在信号衰减。

## 适用与不适用

| 场景 | 做法 |
| --- | --- |
| 本地开源模型，可改隐藏层 | 冻结基座，早期单层注入微型 LoRA 做中继放大 |
| 闭源商业接口，无法挂载权重 | 跳过本节，走协议侧补偿（见下） |
| 短链任务为主 | 不需要注入，收益不抵维护成本 |

## 权重侧流程

1. **冻结基座**：全部原始权重不参与训练，只训练注入模块。
2. **选点**：在早期单层注入，候选层位与秩 r 组成候选集合。注入点越早，能影响的后续层越多。
3. **对照评测**：同一长链评测集下，记录每个候选的多跳因果链条推导成功率，与未注入基线对比。
4. **回归检查**：验证是否引入短链退化、输出格式漂移或能力遗忘。短链指标下降必须在可接受阈值内。
5. **固化**：留档数据版本、随机种子与消融结果，保证可复现。

**通过判据**：多跳链条成功率可重复提升，且短链无显著退化。无提升则回退基座，并把结论登记为「该任务不适用权重侧补偿」。

## 协议侧替代路径

商业 API 不能改权重，用两条路补：

1. **强制思维链展开**：把原本发生在隐藏层的中继搬到可见 token 空间，通过 `dco-skill-explicit-chain-reasoning` 实现。
2. **端侧协同前置路由**：本地挂载微型权重的开源小模型先做长链实体解析，把提炼后的确定性上下文喂给云端大模型，降低云端需要跨越的跳数。

前置路由的收益点在于：跳数减少 → 信号衰减窗口变短 → 过早停机概率下降。

## 反模式

- 不冻结基座，全量微调后把泛化退化误判为注入失败。
- 只看最终答案对不对，不看链路是否可复现。
- 在多层同时注入，无法归因是哪一层起作用。
- 用商业 API 硬凑权重侧方案（做不到，别浪费时间）。
